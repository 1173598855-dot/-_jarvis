# Audit Reporter — 迭代审计报告生成技能

## 触发条件

"生成审计报告"、"迭代总结"、"系统状态报告"、"演进报告"。
每轮迭代结束时自动激活。
也可通过 `/audit` 手动激活。

---

## 执行协议

### 第一步：收集本轮迭代数据

从当前会话上下文收集以下信息：

**架构变更**：
- 使用 `Grep` 搜索本轮创建/修改的文件
- 使用 `Glob` 确认新增文件
- 从 `TaskList` 获取已完成任务

**安全事件**：
- 检查 `RISK_COMPONENTS.log`（如存在）
- 记录拦截的高危调用数量
- 记录沙箱运行状态

**UI 变更**：
- 使用 `mcp__cowork__list_artifacts` 获取当前 Artifacts
- 记录新增/优化的 Widget

**测试结果**：
- 从会话上下文提取测试通过/失败状态
- 记录自动修复的 Bug 数量

### 第二步：生成标准化审计报告

使用 `Write` 工具创建报告文件 `AUDIT_REPORT_N.md`（N 为轮次）：

```markdown
## 🤖 小奕自演进第 [N] 轮迭代审计报告

**迭代时间**：[当前 ISO 时间戳]  
**系统状态**：🟢 健康 / 🟡 警告 / 🔴 异常

---

### 1. 本轮完成演进

**重构/新增模块**：
- [模块名称]：[具体变更描述，引用文件路径]
- [模块名称]：[具体变更描述]

**架构健康度**：
- 层级依赖符合度：[X]%
- 技术债减少：[X] 项
- 新增测试覆盖：[X]%

---

### 2. GitHub 学习与萃取

**参考开源项目**：
- [项目名](链接) ([★] Star) — 关注点：[具体关注点]

**萃取成果**：
- 提取了 [能力名称]，重构为小奕组件：`@core/xxx`
- 使用 `save_skill` 持久化为技能：[技能名称]

---

### 3. 🛡️ 安全审计

**静态 AST 扫描**：
- 扫描文件数：[X]
- 拦截风险调用：[X] 处
- 高风险项归档：`RISK_COMPONENTS.log`

**沙箱运行状态**：
- Python Skill 沙箱：[X] 个运行中
- JS/TS Plugin 沙箱：[X] 个运行中
- 权限授予：最小权限原则 ✅

**回滚验证**：
- 最后一次回滚：[时间]
- 原因：[具体原因]
- 恢复状态：✅ 成功 / ❌ 需人工介入

---

### 4. 🎨 UI 体验优化

**Widget 变更**：
- 新增：[组件名称]
- 优化：[组件名称]（性能提升 [X]%）

**监控面板**：
- 使用 `create_artifact` 创建：[面板名称]
- FPS：[X]（目标 ≥ 60）
- 内存占用：[X] MB

**视觉质量**：
- 毛玻璃层级应用：[X] 处
- 粒子特效状态：[X] FPS 下流畅运行

---

### 5. 自动化测试与缺陷修复

**测试覆盖指标**：
- 单元测试覆盖率：[X]%（目标 ≥ 80%）
- 集成测试通过率：[X]%（目标 100%）
- UI 自动化测试通过：[X]/[Y]

**修复的潜在 Bug**：
- 解决了 [问题描述] 引起的 [具体影响]

---

### 6. 下一轮演进计划

**侦测到的优化机会**：
- [性能瓶颈描述] → 下一轮重点优化方向
- [架构欠缺描述] → 下一轮重构方向

**自动进入下一轮迭代。**
```

### 第三步：持久化与展示

1. 使用 `Write` 保存报告至项目根目录
2. 使用 `mcp__cowork__present_files` 展示报告给用户
3. 使用 `consolidate-memory` 技能记录本轮关键决策到记忆系统

---

## 输出物

1. `AUDIT_REPORT_N.md` — 标准化迭代审计报告
2. 记忆系统更新（通过 `consolidate-memory` 技能）

---

## 报告生成检查清单

生成报告前，确认以下内容已收集：

- [ ] 本轮所有文件变更（Glob/Grep）
- [ ] 安全事件记录（RISK_COMPONENTS.log）
- [ ] Artifact 状态（list_artifacts）
- [ ] 任务完成状态（TaskList）
- [ ] GitHub 学习成果（WebSearch 结果）
- [ ] 测试结果（从会话上下文提取）
